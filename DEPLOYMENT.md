# GUDD — обновление и проверка на Bothost

Этот файл предназначен для технического ответственного. Памятка по управлению карточками — в [README.md](README.md).

## Конфигурация

Бот работает на Python 3.9+ без внешних библиотек. Точка входа в репозитории — `bot.py`. Bothost получает токен бота из поля Bot Token и предоставляет его приложению как `BOT_TOKEN`. Остальные настройки задаются в переменных окружения Bothost:

```text
ADMIN_IDS=Telegram_ID_администраторов_через_запятую
DB_PATH=/app/data/gudd.sqlite3
SMTP_HOST=SMTP_сервер
SMTP_PORT=465
SMTP_USER=ящик_отправителя
SMTP_PASSWORD=пароль_приложения
REPORT_TO=адрес_получателя
```

`SMTP_FROM` необязателен; по умолчанию равен `SMTP_USER`. Локальный `.env` с токеном и паролем не загружается в Git. База `/app/data/gudd.sqlite3` сохраняется между обновлениями кода. Одновременно должен работать только один экземпляр бота с этим токеном.

Фотографии каталога лежат в `media/` рядом с кодом. Не удаляйте эту папку при обновлениях: бот загружает изображения из неё в Telegram при открытии карточки. Исходный ZIP с Яндекс Диска и XLSX на сервере не нужны.

## Обновить код

1. Отправьте проверенный код в ветку `main` GitHub-репозитория `AntonIsaev2004/gudd-tg-bot`.
2. В панели Bothost откройте бота и нажмите **«Обновить из Git»**, если автообновление не включено.
3. Проверьте логи: после сборки должна появиться строка `Бот @Gudd_centr_nedvizhimosti_bot запущен`.
4. В Telegram отправьте боту **/start**, проверьте **«Объекты. Аренда (не пересылать)»** и **«Объекты. Продажа (не пересылать)»**, затем откройте **/admin** от имени администратора.

Обновление текста письма не требует изменения структуры базы. Уже отправленные письма останутся прежними.

## Загрузить новые объекты из таблицы

Каталог из `catalog.json` применяется **автоматически при запуске**, если его версия ещё не загружена. Для версии от 08.10.2026 достаточно обновить код и перезапустить бота. В логах первого запуска появится `Каталог обновлён: 11 объектов`.

У существующих карточек обновляются данные из новой таблицы, обе цены и фотографии. ID, история просмотров, пользователи, отметки отправки писем, порядок и статус «скрыт» сохраняются. Чтобы сопоставить старые карточки, бот использует исходную папку фотографий, а при её отсутствии — прежнее название или адрес. При неоднозначном совпадении обновление отменяется целиком и бот пишет причину в логах. Сама таблица и ZIP на сервере не нужны.

Каждая версия применяется один раз: при следующих перезапусках правки администраторов не перезаписываются и удалённые карточки не создаются заново. Импорт выполняется одной транзакцией. Старые демонстрационные карточки, если они ещё остались, удаляются вместе со своими просмотрами.

При необходимости проверить подготовленный каталог или применить его вручную выполните в терминале бота:

```sh
python3 /app/import_catalog.py
python3 /app/import_catalog.py --apply
```

Первая команда проверяет `catalog.json` и наличие всех изображений, не меняя базу. Вторая применяет ещё не загруженную версию. Если версия уже применена при старте, команда сообщит об этом. После обновления отправьте боту `/start`, сравните обе цены одного объекта, проверьте адрес, фото и возврат в нужный раздел. Если фото не отправляются, проверьте, что папка `/app/media/` попала в обновление из Git.

Подготовка каталога на компьютере разработчика из обновлённых XLSX и ZIP требует `openpyxl` и `Pillow` и описана в `tools/build_catalog.py`; на Bothost эти библиотеки не требуются.

## Проверить базу и почту

В терминале бота на Bothost запускайте команды по одной:

```sh
python3 /app/verify.py
```

Команда проверяет целостность SQLite и показывает число пользователей, просмотров и последнюю плановую отправку. После открытия карточки в Telegram число просмотров должно вырасти.

```sh
python3 /app/verify.py --send-test-email
```

Команда отправляет письмо с темой `[ТЕСТ]` на адрес из `REPORT_TO` и **не сдвигает расписание**. Сообщение «принята SMTP» означает, что сервер отправителя принял письмо; получение проверьте во «Входящих» и «Спаме». Письмо содержит HTML для телефона и текстовую версию.

Проверка кода локально из корня репозитория:

```sh
python3 -m unittest discover -s tests -v
```
