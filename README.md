# GUDD — Telegram-каталог недвижимости

Бот [@Gudd_centr_nedvizhimosti_bot](https://t.me/Gudd_centr_nedvizhimosti_bot) показывает объекты недвижимости кнопками в личном чате. Администраторы управляют карточками в том же боте. Данные хранятся в SQLite; для работы нужен Python 3.9+ без внешних пакетов.

## Как пользоваться каталогом

1. Откройте бота и отправьте `/start`.
2. Нажмите кнопку объекта: в ней указаны название, площадь и цена.
3. Бот покажет фотографии одним альбомом и описание под первой фотографией. Кнопками под альбомом можно перейти к соседнему объекту или вернуться к списку.
4. «💬 Связаться с менеджером» открывает личный чат [@gudd_manager](https://t.me/gudd_manager). Сообщение менеджеру пользователь отправляет самостоятельно.

Бот сохраняет Telegram ID, ник, имя и фамилию (если они есть в профиле), время открытия объекта и его номер. **Телефон бот не запрашивает и не получает автоматически.**

### Команды посетителя

| Команда | Что делает |
| --- | --- |
| `/start` | Показывает каталог объектов |
| `/catalog` | Снова показывает каталог |
| `/help` | Показывает список команд |
| `/id` | Показывает ваш числовой Telegram ID |

## Админка

Админка открывается командой `/admin` только для Telegram ID, перечисленных в `ADMIN_IDS`. Проверяется именно числовой ID отправителя, а не изменяемый никнейм. ID @kot_kokos69 и @Olga_svet06 уже указаны в локальном `bot/.env`. При размещении на сервере перенесите это значение в переменную окружения `ADMIN_IDS`. Чтобы добавить другого администратора, попросите его отправить боту `/id`, затем добавьте полученное число через запятую и перезапустите бота. Формат настройки:

```text
ADMIN_IDS=123456789,987654321
```

Пока `ADMIN_IDS` пуст, админка закрыта для всех. Посетители могут отправить `/admin`, но получат отказ; чужие нажатия на кнопки админки тоже отклоняются.

### Команды администратора

| Команда | Что делает |
| --- | --- |
| `/admin` | Открывает меню управления объектами |
| `/cancel` | Отменяет текущий пошаговый ввод |
| `/done` | Завершает загрузку фотографий |
| `/skip` | Пропускает необязательное поле, когда бот его запрашивает |

Чтобы добавить объект, выберите **«➕ Добавить объект»** в `/admin`, затем по очереди отправьте название, цену в рублях, площадь, локацию, комнатность, краткое и полное описание, особенности и от 1 до 10 фотографий. После фото отправьте `/done` и подтвердите сохранение. Краткое описание и особенности можно пропустить командой `/skip` на соответствующем шаге.

Чтобы изменить объект, откройте **«🏠 Список объектов»** и выберите карточку. В меню можно поменять любое текстовое поле, добавить или удалить фото, скрыть или показать объект, изменить порядок, снять пометку «демо» либо удалить карточку. Удаление требует подтверждения. Фото хранятся как Telegram `file_id`, отдельное хранилище изображений не требуется.

## Почтовая сводка

Письмо на `gudd22@mail.ru` отправляется **по понедельникам и четвергам в 10:00 МСК**. Понедельничное письмо охватывает период с предыдущего четверга 10:00 до понедельника 10:00; четверговое — с понедельника 10:00 до четверга 10:00. Начало включено, конец не включён, поэтому просмотры не попадают в два письма. В сводке есть просмотры и уникальные посетители по каждому объекту, ник, имя, фамилия, Telegram ID, количество просмотров и время первого и последнего просмотра каждого посетителя за период. Объекты без просмотров тоже перечислены. Телефоны в письмо не включаются.

Если бот был выключен в момент отправки, он отправит пропущенные периоды после запуска. Отметки об успешно отправленных письмах хранятся в SQLite. При обрыве между приёмом письма SMTP и записью отметки возможен повтор письма.

Для включения рассылки укажите в `.env` данные **ящика отправителя**. Если это почта Mail, пример такой:

```text
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_USER=адрес_ящика_отправителя@mail.ru
SMTP_PASSWORD=пароль_для_внешнего_приложения
REPORT_TO=gudd22@mail.ru
```

Почта Mail требует [пароль для внешнего приложения](https://help.mail.ru/mail/login/mailer/); обычный пароль от ящика для SMTP не подходит. При другом почтовом сервисе укажите его SMTP-сервер и порт SSL/TLS. `SMTP_FROM` задаётся отдельно только при необходимости; по умолчанию используется `SMTP_USER`. Адрес получателя берётся только из `REPORT_TO`; строка о почтовой сводке при запуске показывает его текущее значение. Если SMTP включён, а `REPORT_TO` пуст, бот сообщит об ошибке настройки. Не публикуйте пароль и токен в репозитории. Пока `SMTP_HOST`, `SMTP_USER` и `SMTP_PASSWORD` пусты, рассылка выключена.

## Файлы и запуск

В папке `bot/` находятся весь запускаемый код, тесты, инструкция, локальная конфигурация `.env` и база `data/gudd.sqlite3`. Файл `.env` и папка `data/` исключены из Git правилами `.gitignore`. Токен нового бота нужно записать в `bot/.env`:

```text
BOT_TOKEN=токен_нового_бота_из_BotFather
```

Запустите из папки `bot/`:

```sh
cd bot
python3 bot.py
```

Можно запускать и из корня проекта командой `python3 bot/bot.py`: пути к `.env` и базе определяются относительно скрипта. При первом запуске SQLite создаётся автоматически и в неё один раз добавляются демонстрационные объекты. Уже существующая база после переноса лежит в `bot/data/gudd.sqlite3` и сохраняет прежние данные. Перед заменой демо-объектов реальными сделайте копию базы. Проверить код без Telegram и SMTP можно командой `python3 -m unittest discover -s tests -v` из папки `bot/`.

### Проверка базы и почты

Из папки `bot/` выполните:

```sh
python3 verify.py
python3 verify.py --send-test-email
```

Первая команда читает базу без изменений: проверяет целостность SQLite и связи между таблицами, показывает число объектов, пользователей и открытий карточек, последние открытия и отметку о последнем регулярном письме. Для проверки новой записи откройте объект в боте и повторите команду: число просмотров должно увеличиться на один. Вторая команда отправляет на адрес `REPORT_TO` тестовую сводку с просмотрами от последнего понедельника или четверга 10:00 МСК до текущего момента. Тестовое письмо имеет тему `[ТЕСТ]` и **не меняет** отметку плановой отправки. Сообщение «принята SMTP» означает, что почтовый сервер принял письмо; его появление во «Входящих» или «Спаме» проверьте в ящике получателя.

Чтобы посмотреть сами записи, из папки `bot/` откройте SQLite в режиме только чтения:

```sh
sqlite3 -readonly data/gudd.sqlite3
```

В появившемся приглашении `sqlite>` выполните:

```sql
.headers on
.mode column
.tables
SELECT id, title, price, area, is_active FROM properties;
SELECT telegram_id, username, first_name, last_name, first_seen_at, last_seen_at FROM users;
SELECT id, telegram_id, property_id, created_at FROM user_events WHERE event_type = 'property_opened' ORDER BY id DESC LIMIT 20;
SELECT period_end, recipient, sent_at FROM report_deliveries ORDER BY period_end DESC;
.quit
```

Времена в базе записаны в UTC. Файл можно также открыть в DBeaver как базу SQLite; таблицы находятся в разделе `Tables`. Не редактируйте рабочую базу вручную без резервной копии.

Для размещения на Bothost загрузите в GitHub/GitLab **содержимое папки `bot/`** как отдельный репозиторий и укажите точку входа `bot.py`. **Не загружайте локальный `.env` с токеном и паролем** в репозиторий; на платформе задайте `BOT_TOKEN`, `ADMIN_IDS`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `REPORT_TO` как переменные окружения. Для сохраняемой базы задайте `DB_PATH=/app/data/gudd.sqlite3`. Если нужны уже накопленные локальные посещения, остановите локального бота и загрузите файл `bot/data/gudd.sqlite3` через файловый менеджер Bothost в `/app/data/gudd.sqlite3` до первого запуска на сервере. Если накопленные данные не нужны, база создастся при первом старте. На сервере должен работать только один экземпляр бота в режиме long polling, иначе Telegram вернёт конфликт. Проверьте доступ сервера к Telegram API и SMTP-серверу.

Если бот не подключается к Telegram, проверьте доступ из терминала: `curl -I --connect-timeout 5 --max-time 8 https://api.telegram.org`. При локальном HTTP-прокси укажите `BOT_PROXY=http://127.0.0.1:порт`. MTProto-прокси Telegram в `BOT_PROXY` не подходит.
